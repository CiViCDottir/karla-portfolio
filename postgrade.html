PostGrade: Student Assessment Management System

Aug – Oct 2026 Team project GitHub ↗

The problem

Sorting, identifying and returning marked assessment scripts by hand takes lecturers a lot of time and invites mistakes. PostGrade helps lecturers handle this: it identifies student numbers in uploaded scripts, lets the lecturer verify each match, and returns the verified file to the student by tracked email. It does not enter or calculate marks.

My role

On the analysis and documentation side, I wrote the macro-forces (PESTEL) analysis, the requirements statement, the product perspective, features and user overview, the external interface requirements, and the integration and scope management sections, including scope control and Phase 1 versus a possible Phase 2.

On the development side, I built the website preview and worked on the Django backend: validating and authorising access to submission files, managing the file lifecycle, hardening the class-list CSV import, and documenting the API.

Approach

Our team of students built PostGrade as a Django REST API backend with a separate Vue.js frontend. The backend covers courses, student class lists, validated CSV imports and assessments, with search, filtering and a dashboard of counts. Lecturers upload PDF or image scripts, which are queued for student-number recognition with OCR and image processing. The lecturer then verifies the match and requests email delivery, and a background mail worker sends the stored copy with delivery history and retries.

Tools

Python Django Django REST Framework PostgreSQL GitHub Systems Analysis Technical Documentation

Decisions and challenges

Two design decisions stand out. For script files, we agreed that a file could be replaced unless its submission had already been marked, and that the old file is only deleted after the replacement has been safely saved, so that a failed upload never loses data. For the CSV import, we made it all-or-nothing: every row is validated first, all the errors are reported together, and nothing is imported if any row fails. An existing student is never overwritten unless the lecturer explicitly asks for it.

Result

A working backend covering courses, students, validated CSV imports, assessments, script upload with recognition, lecturer verification and tracked email delivery, supported by automated tests and project documentation. Achieving a final grade of 78%
